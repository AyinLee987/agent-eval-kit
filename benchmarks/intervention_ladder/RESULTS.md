# Intervention ladder on long tool chains — results

Which intervention actually fixes an agent silently skipping steps it judges
redundant, and at what cost? Six conditions from free (a sentence of prompt)
to expensive (main agent + 5 specialist subagents), on the same 60 generated
8-step tool chains, measured as matched pairs.

Re-run the statistics with:

```bash
python benchmarks/intervention_ladder/analyze.py \
    benchmarks/intervention_ladder/results_flat_baseline.json \
    benchmarks/intervention_ladder/results_flat_prompts.json \
    benchmarks/intervention_ladder/results_hier.json \
    benchmarks/intervention_ladder/results_hier_ablation.json
```

Full write-up, including how the tasks are generated and how the failure was
localised to a layer: `../../reports/intervention-ladder-evaluation.md`.

## Setup

- **System under test**: the real `ReActAgent` in `agent-harness-from-scratch`,
  LLM = `deepseek-chat`, over that repo's 100-tool synthetic kit
  (`examples/tool_scaling_kit.py`).
- **Tasks** (`tasks_8step.json`, n=60): 8-step tool chains generated by a type
  graph random walk, with ground truth obtained by *executing* the chain (every
  tool in the kit is a pure function, so labelling cost is zero). 100% of tasks
  carry at least one "redundancy trigger" — a step that looks skippable:
  T1 no-op round 78%, T5 identity round trip 73%, T4 same tool twice 62%,
  T3 small stat 32%, T2 inferable boolean 18%.
- **k = 3** trials per task per condition; 180 runs per condition, 1,080 total.
- **Unit of analysis is a task, not a run.** With 3 trials the per-task pass
  rate is a continuous score in {0, ⅓, ⅔, 1}; treating 180 runs as independent
  would triple-count each task.
- **Statistics**: `agent_eval.stats.bootstrap_ci` and `paired_bootstrap_test`,
  10,000 resamples, matched over the same 60 tasks.

## Conditions

| Condition | Registry | Prompt change |
|---|---|---|
| `baseline` | flat, 100 tools | shipped default (which ends "when you have enough information … do not call any more tools") |
| `instruction` | flat, 100 tools | that clause replaced by an explicit completeness rule |
| `fewshot` | flat, 100 tools | `instruction` + two worked examples executing a redundant step |
| `hierarchical_bare` | main + 5 specialists | specialist prompt's anti-skip sentence **removed** |
| `hierarchical` | main + 5 specialists | shipped specialist prompt (which already contains an anti-skip sentence) |
| `hierarchical_fewshot` | main + 5 specialists | shipped specialist prompt + a worked example |

## Four things this establishes

1. **Only demonstrations move the headline metric.** `fewshot` is the sole
   condition with a significant exact-match gain (+17.8pp, p=0.0066).
2. **A rule alone trades one failure for another.** `instruction` takes step
   recall from 0.838 to 0.972 and cuts `skip` failures 55 → 6, yet exact match
   does not move at all (−0.6pp, p=0.86) because unrequested calls rise 185 →
   393. "Never skip a step" is an undirected command.
3. **The architectural arm's benefit is its prompt, not its architecture.**
   The shipped specialist prompt already contained an anti-skip instruction.
   Deleting that one sentence (`hierarchical_bare`) and changing nothing else
   drops step recall to 0.867 (+0.029, **p=0.227, not significant**) and
   returns `skip` failures to 52, essentially the flat baseline's 55. Routing
   alone buys 7 delegations per run and no measurable accuracy.
4. **Optimising the headline metric alone would mislead.** `fewshot` wins
   exact match by 17.8 points while being 13.3 points *worse* than doing
   nothing on final-answer accuracy. Only the hierarchical arms leave answers
   intact.

## Caveats — read before citing a number

- **One model** (`deepseek-chat`), one run of each condition at k=3.
- **Synthetic tasks.** Chains are generated and sometimes absurd
  ("base64-encode it, decode it, encode it, decode it"). That is the
  redundancy pressure under test, not natural user traffic.
- **The few-shot examples are pattern-adjacent.** They use tools absent from
  the task set but do demonstrate the T1 and T5 patterns, which are the two
  largest trigger classes.
- **`instruction` changes two things at once** — it removes the early-stop
  clause *and* adds the completeness rule. The ablation separating them has
  not been run.
- **`hierarchical_bare` removes one sentence, not the concept.** It shows the
  shipped prompt carries the benefit; it does not prove no specialist prompt
  could make routing pay off.
- **The 5-step pilot** (`results_5step_pilot.json`) is k=1 on 21 hand-written
  tasks and is included only because it is what motivated this benchmark: its
  conclusions reversed at 8 steps, and re-running its *unchanged* baseline
  scored 71.4% against 57.1% three weeks earlier. Do not cite it.
