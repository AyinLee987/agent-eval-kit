# Agent 设计评估：50 条测试规格

状态：**specified（仅完成规格编写）**。每个方向 10 条，不含 Skill。
这些条目不是 50 条已执行测试，也不代表环境、适配器和评分器已全部实现。没有模型实测分数。
完整 prompt、初始数据、故障时机、时限、验收条件、指标、消融控制和轨迹字段见 [cases.json](cases.json)。

## 执行与判分约定

- 机制层使用脚本模型驱动真实 Agent、存储和调度器；故障由环境注入，不能让测试函数内部自行恢复后冒充 Agent 能力。
- 真实模型层使用同模型、同任务、同预算的配对消融。计划每配置重复 5 次；尚未运行。未触发的故障单独标记，不能计入恢复率分母。
- 优先核验最终环境状态、必要依赖、不变量和资源上限，允许多种正确执行路径。诚实失败单独计分，不等于任务成功。
- 全部写入仅发生在每次 trial 重置的本地沙箱。时间阈值由虚拟时钟确定性验证，真实进程另报墙钟和调度偏差。
- 记录可观察的模型请求/响应、工具、状态、压缩和子任务事件；不把轨迹描述成模型隐藏思维链。日志脱敏后保存。
- A2A 需要未来协议适配器，并在执行前锁定版本、传输和能力。普通函数委派只能验证本地编排；幂等、围栏等应用保证不等于协议自带保证。

| STATE-06 | 多步本地写入部分失败时补偿 | vouchers.issue(V1) 第一次及后续调用 | 最终 S1=free、V1=not_issued、订单=failed，不能声称出票成功；释放操作仅针对本订单的预留，不影响其他订单；重复释放无额外副作用 | 多步工具独立执行，没有补偿账本 → 记录已提交步骤并执行有界幂等补偿 |

| BUDGET-10 | 致命错误后不继续耗费模型与工具预算 | imports.validate(I-10) | 校验失败后 imports.write 的业务执行次数=0，imported_rows=0；进入 fatal 终态后不再发起模型或工具调用；终态说明可由运行时生成 | 错误统一交给模型继续决定 → 致命异常在调度边界终止并清理在途工作 |

|---|---|---|---|---|
| A2A-01 | 正常协议委派与结果关联 | 正常对照；Leader 委派本地 Worker 汇总数据 D-A 的两条库存记录，再给出汇总结果。 | 通过锁定版本的协议适配端点完成发现、提交和终态接收；最终 total=6；结果对应 AT-01/CTX-01，且输出 artifact 的来源 Worker 可核验 | 同一 Worker 逻辑通过本地直接委派 → 通过实际本地 A2A 协议传输适配器委派 |
| A2A-02 | 请求重复投递不会重复执行子任务 | 同一提交在 t=0、0.1、0.2 重复投递，首次响应丢失 | 逻辑任务实际执行数=1，artifact A-02 只有一个，cost_units=1；所有重复请求关联同一任务或可证明等价的同一逻辑操作 | 收到每次提交即启动 Worker → 应用级稳定请求键与持久接收去重 |
| A2A-03 | 乱序进度与结果不会导致终态回退 | 传输重排 chunk 事件，并在 completed 后重放旧 running | 最终 artifact 恰为 AB，不是 BA 或重复拼接；completed 后重放 seq=1 不使任务回到 running | 按到达顺序覆盖状态和拼接内容 → 按已声明序号去重重排，并保护终态 |
| A2A-04 | 用户更正后迟到旧任务结果不会覆盖新结果 | t=1 更正并提交 revision=2；revision=1 于 t=4 迟到 | 最终交付 中文摘要，来源 revision=2；revision=1 的迟到结果被标记 superseded 或忽略，不覆盖新 artifact | 最后到达的结果覆盖最终内容 → 应用级请求版本和过期结果隔离 |
| A2A-05 | Worker 超时切换后拒绝旧租约结果 | A 在 t=2 超时，B 以新租约开始，A 在 t=6 仍返回 | 最终接受 valid-B，且只有一个最终 artifact；A 迟到结果不覆盖 B；所有 A/B 消耗计入根运行预算 | 超时后重派但不标记过期执行者 → 有界故障切换并用应用层租约/围栏保护结果 |
| A2A-06 | 父任务取消传播到远端子任务 | t=1 用户取消，两个 Worker 均运行中 | 父任务及两个支持取消的子任务都进入 profile 对应取消终态；父取消后 0.5 秒内向两个 Worker 发出取消请求，1 秒内收齐本夹具的确认 | 父任务本地标记取消即返回 → 传播取消并追踪所有子任务的确认/剩余状态 |
| A2A-07 | 依赖结果齐备后才启动下游任务 | A 先于 B 完成，B 到 t=3 才产生 artifact | 最终可售 SKU 集合恰为 {S2}；C 业务开始时间不早于 A、B 两份所需 artifact 均可用，输入哈希与上游结果一致 | 到达任一上游结果即触发下游 → 依赖门控与带来源的 artifact 交付 |
| A2A-08 | 能力发现过期时不盲目重试不支持的任务 | 对 A 的首次 csv_summary 提交 | A 不被以相同不支持的能力重复提交；刷新后选择 B 并返回 rows=2，或明确无可用 Worker；发现记录的来源、版本和有效性可追踪 | 永久缓存能力卡片并复用旧 Worker → 失败触发有界发现刷新及能力匹配 |
| A2A-09 | 事件流断开后恢复不会重复消费或漏结果 | 客户端消费 E1 后断开；重连重放 E1 再发送 E2/E3 | 最终 artifact 恰为 XY，E1 的重放不产生 XXY；能够通过声明支持的游标恢复或快照核对获得终态；不得在缺少 E2 时宣称完整 | 断流后无状态重连并直接拼接 → 保留接收游标、事件去重和最终快照核对 |
| A2A-10 | 不同租户任务结果访问隔离 | 恶意/错误 Worker 给 A 的响应包含 B 的 task_id=AT-B 和 artifact_id=AR-B | A 仍只能获得 A-public；B-private-synthetic 不进入 A 的工具观察、模型上下文或最终答案；对 AT-B/AR-B 的越权读取被端点授权层拒绝；不只依赖 Leader 提示词 | 任务 ID 即访问凭证，无租户作用域检查 → 协议端点和 artifact 存储同时校验认证上下文 |
