# Robustness Evaluation Report

**System under test:** the real `ReActAgent` in `agent-harness-from-scratch`,
running Alibaba Bailian's `qwen-plus`, asked the same underlying question
four different ways.
**Toolkit used:** `agent_eval.similarity` (new — `cosine_similarity` /
`average_pairwise_similarity`), plus the existing `EvalHarness`,
`RuleScorer`, and `ToolUsageScorer`.
**Benchmark code:** `benchmarks/robustness/` (`queries.py`, `tools.py`,
`cached_embeddings.py`, `run_benchmark.py`). Re-run with
`python benchmarks/robustness/run_benchmark.py`.
**Raw output:** `benchmarks/robustness/results.json`.

---

## 1. Objective

Every other benchmark in this project asks *one* wording of a question and
grades the answer. That can't tell you whether an agent is actually
reasoning about a request or pattern-matching a specific phrasing — and
production traffic is never one canonical phrasing. This evaluation asks
the same underlying request four ways and measures how much the agent's
*answer* moves:

- a same-language **paraphrase** (different vocabulary/structure, same
  meaning),
- a **register shift** (formal wording, or an irrelevant politeness
  preamble wrapped around the request),
- a **translation** into a different language (Chinese → English).

Higher similarity across the four answers means the agent is responding to
the underlying request, not the specific surface form it was asked in.

## 2. Methodology

### 2.1 Base questions and variants (`queries.py`, n=8)

| id | tool | tests |
|---|---|---|
| `calc-basic` | calculator | single arithmetic expression |
| `calc-compound` | calculator | multi-step arithmetic expression |
| `lookup-pto` | lookup_fact | single fact lookup |
| `lookup-ratelimit` | lookup_fact | single fact lookup |
| `chain-stipend` | (lookup_fact + calculator) | tool chaining |
| `datetime-check` | current_datetime | tool call with no fixed expected value |
| `fact-speed-of-light` | none | open-ended factual knowledge |
| `fact-boiling-point` | none | closed-form factual knowledge |

Each question is written in Chinese as the base wording, with three
pre-authored variants — not generated by an LLM at run time, for the same
reason the RAG benchmark's lexical/paraphrase queries are pre-authored:
reproducible, and it avoids grading a translation the same system
implicitly produced. English was chosen as the one translation target
(rather than a second non-English language) to keep the set small while
still crossing a real language boundary — both the agent model and the
embedding model are strong in both languages, so a similarity drop can be
attributed to the agent's behavior rather than either model's weaker
language.

Tool selection deliberately covers both no-tool and tool-requiring
questions: rewording can change whether the agent even recognizes a tool is
needed, which a same-language-only test would never surface.

### 2.2 Scoring

Each of the 32 (question × phrasing) combinations runs as an independent
single-turn task — a fresh agent per task, matching every other benchmark
in this project.

- **Primary — pairwise answer similarity.** Each phrasing's final answer is
  embedded with the same real `qwen3.7-text-embedding` endpoint the RAG
  recall benchmark requires (this benchmark refuses to run without it, for
  the same reason: a hash-based mock embedding would make "similarity"
  meaningless). `average_pairwise_similarity` (`agent_eval/similarity.py`,
  new this run) averages cosine similarity over all 6 unordered pairs among
  a question's 4 answers.
- **Secondary — content/tool correctness.** `RuleScorer` (expected
  substrings — deliberately restricted to language-invariant content, i.e.
  numbers, since a proper noun would legitimately come back in a different
  language for the English translation than for the Chinese phrasings, and
  fail the check for the wrong reason) and `ToolUsageScorer` (the same tool
  actually gets invoked regardless of phrasing/language) run per phrasing.
  This exists because similarity alone cannot distinguish "four
  consistently correct answers" from "four confidently wrong in the same
  way" — a robustness score with no correctness floor underneath it isn't
  worth much.

one was needed, the correct tool.

## 4. Why `chain-stipend` scored lowest — and it isn't an inconsistency

All four phrasings correctly computed **$600** (3 on-call shifts × $200/
shift). Here's what differs:

| Phrasing | Answer |
|---|---|
| `base` | "oncall_stipend_usd 的值是 200 美元，一个季度值班 3 次总共是 600 美元。" |
| `paraphrase` | "一个季度轮值3次的总金额是600美元。" |
| `register` | "oncall_stipend_usd 的值是 200 美元，一个季度值班 3 次总共需要支付 600 美元。" |
| `translation` | "The on-call stipend per shift is $200. For 3 on-call shifts in one quarter, the total is $600." |

`paraphrase` states only the final total; the other three restate the
looked-up intermediate value ($200) before it. The embedding model is
picking up on **verbosity and structure**, not a difference in correctness
— all four say $600.

This is the same pattern on two other below-average questions, confirming
it isn't a one-off:

- `fact-speed-of-light`: `base` answers with just the number
  (`299{,}792{,}458` m/s); `paraphrase` adds an extra sentence naming it a
  physical constant ("记作 **c**"); `register` and `translation` both add
  the ×10⁸ approximation. Same fact, different amount of elaboration.
- `datetime-check`: all four answers report the same UTC timestamp to the
  second (as expected — the tool call happens seconds apart across the four
  runs) but differ slightly in formatting (`现在是 UTC 时间 ... 08:05:44`
  vs. `当前的日期时间是：... 08:05:49（UTC）` vs. an English sentence).

**Takeaway:** the benchmark's own plan flagged this risk before running —
"embedding cosine similarity is coarse for short factual answers" — and
this run supplies the concrete mechanism, not just a hypothetical one: for
short, numeric-answer questions, *how much the agent elaborates* moves the
embedding more than *whether it's phrased differently or in another
language* does. A robustness score built this way is better read as "did
rewording change what the agent computed" (yes, robust — confirmed
separately by the secondary metrics) than as a single number capturing
"how similar the wording of the response was."

## 5. Threats to validity

- **n=8 questions / 32 phrasings** is small — enough to cover both
  no-tool and tool-requiring questions and a real language boundary at
  least once each, not enough to claim a stable "robustness score" for the
  agent in general.
- **One embedding model, one agent model, one run** — no repeated sampling,
  so a given similarity number carries whatever variance a single Bailian
  `qwen-plus` response happens to have that run (illustrated directly by
  §4: re-running would likely reshuffle exactly *how* verbose each
  phrasing's answer is, and with it, the exact similarity number — while
  the secondary correctness metrics would very likely stay at 1.00).
- **Variant wording is hand-authored, not adversarial.** These are natural
  rewordings a real user might produce, not designed to break the agent
  (that's closer to ③ safety's remit). A ceiling-ish correctness result
  here (`rule_pass`/`used_expected_tool` both 1.00) demonstrates the agent
  handles ordinary phrasing variation correctly; it says nothing about
  harder adversarial paraphrasing.
- **What this evaluation supports:** on ordinary paraphrase/register/
  translation variation, this agent's *content* is stable — every one of
  32 phrasings got the right answer and used the right tool. **What it does
  not support:** a single "robustness score" free of the confound this
  report documents (verbosity/formatting variance in the embedding space);
  read the per-question similarity numbers alongside the worked examples in
  §4, not as a standalone ranking.

## 6. Reproducibility

```bash
# from the evaluation/ repo root, with BAILIAN_API_KEY and RAG_EMBEDDING_*
# set in the sibling repo's .env
python benchmarks/robustness/run_benchmark.py
```

Not bit-for-bit deterministic — the agent is a real LLM call for every one
of the 32 phrasings; embeddings are cached by
`sha256(model_id + text)` (`benchmarks/robustness/.embedding_cache.json`,
gitignored) so re-running without changing an answer's text doesn't re-pay
for embeddings, but every agent response is freshly generated each run.
